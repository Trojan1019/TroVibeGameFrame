# 2048 动森 UI 迁移提示词文档

这份文档的目标不是解释“动森风格是什么”，而是把当前仓库里已经存在的三份事实来源，压缩成一套可以直接复用的提示词和执行方案：

- `Game` 项目本身：一个“流程壳优先”的 2048-like sample module
- `交互迁移经验文档.md`：强调手感分层、奖励链路、教程层、主动作单一
- `animal-island-ui/skill/SKILL.md`：提供视觉语言、设计 token、组件气质和 UI 纪律

适用场景：

- 你要继续优化当前 `Game` 项目
- 你要把这套动森壳层迁移到别的 2048、三消、合成、轻解谜 H5
- 你要让 Codex、v0、Figma AI、Claude、Gemini 之类工具稳定产出“像动森、但不是套皮”的结果

---

## 1. 迁移目标

这次迁移的重点不是重写 2048 规则，而是把下面四层从弱状态变成强状态：

1. 交互状态层
   - 明确当前输入状态
   - 明确当前允许动作
   - 明确方向预判和无效反馈

2. 反馈层
   - 合并前有预判
   - 合并中有提交感
   - 合并后有结果感
   - 失败动作有温和但明确的拒绝反馈

3. 奖励层
   - 分数不是静态数字变化
   - 奖励需要从来源飞到 HUD
   - 里程碑需要被庆祝

4. 教程层
   - 首次进入只教一个动作
   - 不用长文案
   - 要用真实焦点区 + 手势引导

一句话目标：

`把当前 2048 从“有壳层的样例页面”提升为“有动森气质、强反馈、低学习成本”的轻游戏流程 demo。`

---

## 2. 风格映射规则

不要直接说“做成 Animal Crossing 风格”。迁移时必须拆成下面这组可执行规则。

### 2.1 视觉气质

- 暖色大地系，不用企业后台蓝灰
- 奶油白、木头棕、草地绿、薄荷青、橙黄点缀
- 大圆角、厚描边、短阴影、像玩具按键
- 不是极简现代，不是扁平 SaaS，不是赛博游戏 HUD

### 2.2 组件气质

- 主按钮：立体、饱满、可按压
- 面板：奶油卡片 + 厚边框 + 暖阴影
- 钱包/数值：胶囊徽章，不是冷冰冰 label
- 标题：像游戏章节标签，而不是网页 H1
- 弹窗：像游戏提示卡，不像系统对话框

### 2.3 动画气质

- 入场用软弹，不用线性滑动
- 强反馈给 150ms - 800ms 动画
- 循环提示低频呼吸，不做高频抖动
- 奖励飞行要有起点、中段放大、终点过冲

### 2.4 交互纪律

- 任何时刻只有一个主动作最显眼
- 反馈分层，不把所有变化堆在一个动画里
- 高频操作反馈要克制，长期看才不会累
- 新手引导只教当前动作，不教系统全貌

## 3. 当前 2048 项目的推荐迁移方向

基于当前仓库结构，推荐这样迁：

### 3.1 不动的部分

- `games/game2048/module.ts`
- `games/registry.ts` 的基本模块注册思路
- `lobby -> playing -> settlement` 流程骨架

### 3.2 优先重做的部分

- `RoundStatusPanel`：作为分数锚点、快速完成和 HUD 节点

### 3.3 后续再扩的部分

- Lobby 首屏入场层
- Settlement 的庆祝链路
- 任务/邮件/商店的奖励飞入联动
- “世界建设感”元进度

## 4. 给 Codex 的核心主提示词

这个提示词适合直接喂给 Codex 做代码实现。

```text
你正在优化一个 React + TypeScript 的 2048-like H5 游戏。

项目事实：
- 这是一个“流程壳优先”的 sample game，不是纯粹的单页 2048。
- 流程骨架要保留：lobby -> playing -> settlement。
- 2048 规则模块尽量保持纯逻辑，不要把动画状态和 UI 状态污染进去。
- 当前目标不是重写玩法，而是补强交互状态、反馈层、奖励层、教程层。

风格目标：
- 采用 animal-island-ui 的视觉语言：暖色大地色、奶油白卡片、厚边框、圆角 pill、立体按钮、柔和阴影、游戏化但克制。
- 整体像动森风格的轻游戏 UI，而不是企业后台、极简仪表盘或赛博 HUD。

交互目标：
- 任何时候只有一个主动作最突出。
- 每个主动作都要在 150ms - 800ms 内得到可见反馈。
- 反馈必须分层：预判、提交、结果、奖励，不要堆成一个动画。
- 首次引导只教一个动作：滑动棋盘。
- 奖励不要直接改数字，要尽量从来源飞向 HUD。

实现约束：
- 优先局部补丁，不要重写整体结构。
- 保持 `games/game2048/module.ts` 纯逻辑。
- UI 状态放在 `GameScreen` 或 view 层容器。
- 优先修改 playing 页，不先重做 lobby 全部视觉。
- 默认移动端优先，同时兼容桌面键盘。

输出要求：
- 先给出你要新增的 UI 状态结构。
- 再说明准备改哪些文件、为什么。
- 然后直接实现，不要只停留在方案。
- 改完后跑构建与类型检查，并说明验证了哪些交互。
```

## 5. 给 Codex 的阶段实现提示词

### 5.1 Phase 1：只做对局交互状态与反馈层

```text
在当前 2048 项目中，只优化 playing 页，不动 2048 规则算法。

目标：
- 补交互状态层
- 补方向预判
- 补无效移动反馈
- 补成功移动脉冲反馈
- 补首次教程层

要求：
- 不要重写 `games/game2048/module.ts`
- 用局部 UI state 管理 gesture / preview / feedback
- 棋盘操作仍然走现有 move dispatch
- 首次教程只教“轻扫任意方向”
- 不要做复杂世界地图、任务联动、全局重构

验收标准：
- 玩家首次进入能看到明确引导
- 玩家拖/滑时能感知当前方向
- 无效移动有温和但明确的反馈
- 有效移动不再只是“数字变了”
```

### 5.2 Phase 2：只做奖励层

```text
继续优化当前 2048 项目，但这次只补奖励层，不重写规则模块。

目标：
- 合并后的分数反馈不再只是数值变化
- 奖励从棋盘来源飞向顶部 HUD 分数区
- 达成更大方块时有里程碑提示
- 升级/道具使用也要有独立奖励反馈

实现要求：
- 奖励飞行必须是独立浮层，不要把动画硬塞在 tile 内部
- 必须有来源位置和目标位置
- 动画轨迹要有中段放大和终点收束
- 保持动森感：暖色、柔和、玩具感，不要做电竞炫光

验收标准：
- 用户能明确感知“为什么加分”
- 用户能感知里程碑被庆祝
- 奖励反馈不遮挡主要操作区域
```

### 5.3 Phase 3：扩展到 Lobby / Settlement

```text
继续沿用当前动森轻游戏 UI 方向，把 2048 项目的 lobby 和 settlement 补完整。

目标：
- lobby 更像游戏入口页，而不是样例壳说明页
- settlement 更像结算庆祝卡，而不是静态数据页
- 不大改流程结构，但加强进入感、结束感和回流感

重点：
- lobby 只保留一个主 CTA
- settlement 强化结果图标、里程碑、重开和回大厅按钮优先级
- 动画要软弹，不要复杂转场
- 保持共享 shell primitives 的思路，不要把样式散落
```

## 6. 给视觉/设计 AI 的页面提示词

适合喂给 Figma AI、v0、Lovable、GPT Image、Midjourney 文生图描述等。

### 6.1 Playing 页视觉提示词

```text
Design a mobile-first 2048 game screen in a warm Animal Crossing-inspired UI style.

Requirements:
- soft cream background with warm wood brown borders
- toy-like rounded square board
- chunky pill score cards
- cute game HUD, not a productivity dashboard
- thick outlines, short depth shadows, soft highlights
- one main playfield in the center
- top area contains score, best score, and two small utility buttons
- lower area contains four item tools with cute counts
- use a cozy, playful, handcrafted look
- motion tone should feel soft, bouncy, and friendly
- avoid flat minimalism, neon cyberpunk, glassmorphism-heavy SaaS layout, and esports styling
- preserve a clean playfield with low UI clutter
```

### 6.2 Tutorial overlay 视觉提示词

```text
Design a first-time tutorial overlay for a mobile 2048 game in a cozy Animal Crossing-inspired UI.

Requirements:
- dim the background outside the board
- highlight the board with a rounded glowing focus frame
- show one swipe gesture guide only
- add a small rounded explanation card with short Chinese text
- visual style should match warm cream and wood tones
- tutorial should feel gentle and beginner-friendly, not like a system alert
- no long text, no multiple steps visible at once
```

### 6.3 Reward flight 视觉提示词

```text
Design a reward animation layer for a cozy mobile 2048 game.

Requirements:
- score reward originates from merged tile position
- reward flies toward the top score HUD
- mid-flight scale up slightly
- endpoint overshoots lightly and settles
- use warm gold and cream tones
- make it feel delightful and toy-like, not flashy or arcade-neon
- animation should read clearly within 700ms
```

## 7. 给实现型 AI 的组件级提示词

### 7.1 棋盘视图组件提示词

```text
Refactor the 2048 board view into a cleaner interaction surface.

Goals:
- support a board feedback state: idle / success / invalid
- support a direction preview state while swiping
- support a tutorial overlay state
- keep tile rendering visually simple but responsive
- do not move game rules into the board view

Constraints:
- board view is presentation-focused
- rule dispatch still comes from the current game module
- prefer explicit props over hidden coupling
```

### 7.2 GameScreen 容器提示词

```text
Turn GameScreen into the UI-state orchestrator for the 2048 playing page.

Responsibilities:
- keyboard and pointer input normalization
- direction preview and threshold handling
- invalid move feedback
- reward flight spawning
- tutorial completion state
- HUD anchor measurement

Constraints:
- keep existing gameplay module pure
- keep save/load flow intact
- do not rewrite app-wide game flow
```

### 7.3 Shell primitives 提示词

```text
Extend the shared shell primitives only where needed to support 2048 interaction upgrades.

Requirements:
- keep primitives reusable
- do not leak gameplay-specific assumptions into generic components
- if a panel needs a DOM anchor ref, add it in a minimal way
- preserve the warm, playful, chunky Animal Crossing-inspired design language
```

## 10. 迁移验收清单

无论你是自己实现还是让 AI 实现，最后都按这个验收。

### 10.1 交互

- 玩家首次进入是否马上知道怎么开始
- 滑动时是否能感知方向预判
- 无效移动是否有明确但不刺眼的拒绝反馈
- 升级模式是否明确告诉用户下一步操作

### 10.2 反馈

- 成功移动后是否不再只是静态重排
- 合并后是否有结果确认
- 高频反馈是否克制
- 是否没有乱闪、乱跳、乱放大

### 10.3 奖励

- 分数增长是否有因果链
- 奖励是否从棋盘来源飞到 HUD
- 更大方块是否被庆祝
- 道具反馈是否和普通合并区分开

### 10.4 风格

- 大厅、对局、结算是否像同一个游戏
- 视觉是否是暖色、圆润、厚描边、游戏化
- 是否避免了 SaaS 仪表盘感
- 是否保住了棋盘可读性
