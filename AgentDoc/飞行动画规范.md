# 飞行动画规范

本项目后续所有“奖励飞行”“金币飞入”“道具飞入”等动画，统一复用 `Game/src/components/flight/RewardFlightProvider.tsx`，不要再在业务页面内临时写一套局部 keyframes。

## 1. 目标

统一解决三类问题：

- 起点和终点跨弹窗、跨面板、跨层级时的坐标不一致
- icon 被 `overflow: hidden`、mask、scroll 容器裁切
- 不同页面各自写一套飞行动画，参数和节奏失控

## 2. 统一实现位置

- Provider：`Game/src/components/flight/RewardFlightProvider.tsx`
- 当前接入：
  - 奖励弹窗 `RewardShowcaseModal`
  - Lobby 顶部货币栏
  - Lobby 背包入口
  - Game 顶部货币栏
  - Game 底部四个道具按钮

## 3. Overlay 规则

飞行动画必须挂在独立的全屏顶层 overlay 容器中，而不是挂在奖励弹窗、列表容器、卡片内部。

当前规则：

- `RewardFlightProvider` 渲染一个 `absolute inset-0` 的 overlay
- overlay 始终位于当前 screen root 最上层
- 所有飞行 icon 都直接挂进这个 overlay
- 业务层只提供：
  - 起点 element
  - 终点 target id / element
  - 奖励种类
  - 奖励数量

## 4. 坐标换算

起点和终点必须统一换算到 overlay 坐标系：

1. 读取 overlay 的 `getBoundingClientRect()`
2. 读取 source / target 的 `getBoundingClientRect()`
3. 使用元素中心点：
   - `x = rect.left - overlayRect.left + rect.width / 2`
   - `y = rect.top - overlayRect.top + rect.height / 2`

禁止直接使用某个弹窗内部的相对坐标或列表项 offset。

## 5. 标准时序

单 icon：

- `gatherDuration`: 150ms
- `gatherHoldDuration`: 100ms
- `flyDuration`: 550ms
- 总时长：800ms

多 icon：

- `launchInterval`: 50ms

缩放：

- `spawnScale`: 0.72
- `popScale`: 1.12
- `endScale`: 0.70

## 6. 标准轨迹

统一采用“两段式”：

1. 起点 -> 起点附近随机散开点
2. 散开点 -> 终点附近随机收束点

参数：

- `gatherScatterRadius`: 80px
- `endScatterRadius`: 8px
- `arcHeight`: 120px

主飞行控制点：

- `control.x = (gather.x + end.x) / 2`
- `control.y = (gather.y + end.y) / 2 - arcHeight`

禁止直接直线飞向终点。

## 7. Easing

- 出生放大：`OutBack`
- 缩放收束：`InQuad`
- 起点到散开点：`OutQuad`
- 主飞行：`InCubic`

## 8. Icon 数量映射

统一公式：

- `iconCount = ceil(sqrt(itemCount))`
- 最少 `1`
- 最多 `10`

示例：

- 1 -> 1 个
- 4 -> 2 个
- 9 -> 3 个
- 100 -> 10 个

## 9. 尺寸规则

- 默认奖励 icon：`100 x 100`
- 道具类 icon：`120 x 150`

参数名：

- `defaultIconSize`
- `propIconSize`

禁止把尺寸写死在具体页面逻辑里。

## 10. Target 注册规则

所有可接收奖励的 UI 节点，统一通过 `useRewardFlightTarget(targetId)` 注册。

当前 target id：

- `wallet-coins`
- `wallet-diamonds`
- `inventory-bag`
- `tool-undo`
- `tool-shuffle`
- `tool-hint`
- `tool-upgrade`

后续新增接收点时，优先扩充 target id，不要在业务页里硬编码 querySelector。

## 11. 完成回调规则

统一顺序：

1. 奖励弹窗点击确认
2. 飞行动画开始
3. 第一枚 icon 到达后，触发目标节点命中反馈
4. 全部 icon 飞完
5. 再执行总完成回调
   - 更新货币
   - 更新库存
   - 标记邮件/签到/任务已领取
   - 关闭奖励弹窗

不要在飞行开始前就提前把数值改掉。

## 12. 当前接入建议

后续如果新增飞行动画，优先按下面模式接：

1. 给起点元素加 ref
2. 给终点元素注册 target
3. 调 `launchRewardFlightGroup`
4. 奖励到账逻辑放到 `onComplete` 后

不要在页面内单独写新的飞行 keyframes。
