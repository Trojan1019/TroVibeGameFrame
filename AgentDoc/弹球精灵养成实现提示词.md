# 弹球精灵养成实现提示词

更新时间：

- 2026-07-06

文档目的：

- 给后续实现代理 / 工程师提供一份可直接复制使用的详细提示词
- 让“数字合成 sample gameplay -> 弹球 + 精灵养成玩法模块”的转换尽量少走偏路
- 保证新玩法能挂接到当前项目流程壳，而不是推倒重做

适用对象：

- 后续 Codex / AI 代理
- 需要在当前仓库里实现新玩法模块的前端工程师

---

## 1. 先读结论

后续实现时，不要把这个项目理解成“做一个新游戏页面”。

正确理解是：

- 当前仓库已经有 `lobby -> playing -> settlement` 流程壳
- 目标是把 `game2048` 这个 sample gameplay，替换成一个新的 `pinball-pet` 模块
- 替换优先级是“玩法模块接入”，不是“全局 UI 重构”

因此，后续实现必须遵守：

1. 保留现有流程壳
2. 保留快速胜利 / 失败测试能力
3. 优先新增模块与适配层
4. 不把高风险共享区当成主战场

## 2. 当前项目接口约束

### 2.1 当前玩法模块接口

当前玩法模块接口定义在：

- `Game/src/framework/gameModule.ts`

核心接口：

```ts
export interface GameModule<TState, TSnapshot, TAction, TMetrics = undefined> {
  id: string;
  createInitialState(snapshot?: TSnapshot): TState;
  toSnapshot(state: TState): TSnapshot;
  dispatch(state: TState, action: TAction): GameActionResult<TState, TMetrics>;
}
```

因此新玩法必须也提供：

- `createInitialState`
- `toSnapshot`
- `dispatch`

### 2.2 当前流程壳约束

当前流程壳定义在：

- `Game/src/framework/gameFlow.ts`

固定三段：

- `lobby`
- `playing`
- `settlement`

新玩法不能跳出这三段流程。

### 2.3 当前 activeGame 组织方式

当前 registry 在：

- `Game/src/games/registry.ts`

后续玩法切换应优先沿用这一层思路：

- 提供 `activeGame.module`
- 提供 `activeGame.view`
- 提供 `activeGame.loadSnapshot / persistSnapshot`
- 提供 `resolveRoundOutcome`
- 提供任务事件适配层

## 3. 新玩法的硬目标

## 3.1 玩法名称

内部代号建议统一使用：

- `pinball-pet`

不要继续沿用：

- `2048`
- `number-merge`

但在真正做大规模重命名前，不要顺手全仓库清洗旧命名。

### 3.2 新玩法一句话定义

- 玩家拖拽瞄准并发射一串球核，利用墙壁与目标反弹清场；球核附带精灵技能，局外通过精灵收集、升级、进化与营地系统持续成长。

### 3.3 首版体验关键词

- 上手快
- 一发打满
- 有上升压迫
- 有精灵人格
- 有长期成长目标

## 4. 首版实现边界

## 4.1 只做 MVP

首版必须克制，不要一开始把策划案里的所有系统都做完。

首版只做：

1. 基础弹球战斗
2. 单局胜负判定
3. 3 只可上阵精灵
4. 4 条基础技能流派
5. 关卡配置与主线推进
6. 结算奖励回流
7. 快速胜利 / 快速失败

首版不要做：

1. 多人实时
2. 公会
3. 复杂活动小游戏
4. 深度营地经营
5. 重装备 / 符文 / 宝石系统
6. 大型 PvP

---

## 5. 核心玩法规格

## 5.1 战斗场基本规则

战斗场采用“最强弹一弹”式基础结构：

1. 玩家从屏幕下方发射一串球核
2. 球核在边界、敌人、障碍、机关之间反弹
3. 每次命中对目标造成固定或系数伤害
4. 回合结束后，敌方单位整体推进或执行行动
5. 任一敌人或危险线推进到失败线，则本局失败
6. 清空当前波次 / Boss 血量，则本局胜利

### 关键差异

不能做成纯打砖块。

战斗对象必须混合三类元素：

1. `敌人`
2. `机关`
3. `增益目标`

#### 敌人

- 普通史莱姆：基础受击单位
- 盾兵：前几次碰撞减伤
- 召唤巢：回合结束产出小怪
- Boss：多阶段技能目标

#### 机关

- 反弹板
- 爆炸桶
- 冻结区
- 传送洞

#### 增益目标

- `+1球`
- `暴击球`
- `分裂球`
- `充能点`

---

## 5.2 单局回合流程

推荐回合顺序：

1. `prepare`
   显示当前波次、敌人站位、可拾取增益

2. `aim`
   玩家拖拽瞄准，显示轨迹预测线

3. `launch`
   发射全部球核

4. `resolve`
   球核持续运动、碰撞、触发技能和机关

5. `collect`
   球核回收到底部，收集本回合额外球数 / 能量

6. `enemyTurn`
   敌方推进、施法、召唤

7. `roundEnd`
   判定胜负，否则回到下一轮 `aim`

### 首版节奏建议

- 单局时长：`60~120秒`
- 单回合操作：`3~8秒`
- 单回合观察：`2~10秒`

---

## 5.3 上升压迫规则

必须保留“线性逼近失败”的压力，否则弹球只是爽，没有驱动。

推荐两种实现，首版选一种：

### 方案 A：敌人整体下压

- 每回合结束，所有敌方单位整体下移一行
- 到达失败线立即失败

优点：

- 最接近最强弹一弹
- 规则最容易理解

### 方案 B：危险能量条累积

- 每回合结束，场景危险度上升
- 危险度满后敌人发动强压制

优点：

- 更容易做怪物技能化

建议：

- `首版用方案 A`

---

## 5.4 精灵如何接到弹球动作上

首版不要做“精灵站桩自己打”，而要让精灵直接绑定到球核逻辑。

推荐结构：

### 队长精灵

决定：

- 球核基础属性
- 主主动技
- 核心流派标签

例如：

- 火狐：反弹 3 次后留下火焰轨迹
- 冰龟：首次撞击附加冻结
- 雷雀：每命中 4 次触发连锁电弧

### 主战精灵

每只主战精灵提供一个被动挂件：

- 暴击提升
- 分裂概率
- 回收增益
- 击杀返能

### 支援精灵

只提供场外光环：

- 开局额外 1 球
- 通关金币加成
- 进化材料掉率提升

## 6. MVP 精灵与流派规格

## 6.1 首版阵容规模

建议：

- 上阵主战：`3`
- 队长：`1`
- 支援：`0~2`

如果实现压力大：

- 第一版直接只做 `1队长 + 2主战`

## 6.2 首版四条流派

### 1. 连击流

关键词：

- 多碰撞
- 分裂
- 连击增伤

目标体验：

- 一回合在场上打很久

### 2. 爆发流

关键词：

- 穿透
- 暴击
- 范围爆炸

目标体验：

- 少碰撞但单次伤害高

### 3. 控场流

关键词：

- 冻结
- 减速
- 吸附

目标体验：

- 敌人推进速度被明显压制

### 4. 孵化流

关键词：

- 召唤小球
- 额外球核
- 击杀孵化

目标体验：

- 球越打越多，战场越来越热闹

## 7. 推荐状态与动作拆分

以下不是必须一字不差照搬，但后续实现应尽量靠近这个结构。

## 7.1 Snapshot

```ts
export interface PinballPetSnapshot {
  stageId: string;
  roundIndex: number;
  score: number;
  balls: number;
  energy: number;
  pets: Array<{
    id: string;
    level: number;
    star: number;
  }>;
  boardSeed?: string;
  enemyState?: SerializedEnemyState[];
}
```

要求：

- Snapshot 必须足够让对局恢复
- 不要求把所有动画中间态存进去
- 恢复时允许从“回合开始”恢复，不要求帧级恢复

## 7.2 Runtime State

```ts
export interface PinballPetState {
  stageId: string;
  roundIndex: number;
  status: RoundOutcome;
  phase: 'prepare' | 'aim' | 'launch' | 'resolve' | 'enemyTurn';
  score: number;
  balls: number;
  energy: number;
  combo: number;
  launchedBalls: BallRuntimeState[];
  enemies: EnemyRuntimeState[];
  pickups: PickupRuntimeState[];
  hazards: HazardRuntimeState[];
  pets: PetBattleState[];
  lastLaunch?: {
    angle: number;
    originX: number;
    originY: number;
  };
}
```

## 7.3 Action

推荐动作：

```ts
export type PinballPetAction =
  | { type: 'start-round' }
  | { type: 'set-aim'; angle: number }
  | { type: 'launch'; angle: number }
  | { type: 'tick'; deltaMs: number }
  | { type: 'use-skill'; petId: string }
  | { type: 'spawn-wave' }
  | { type: 'resolve-enemy-turn' }
  | { type: 'collect-pickup'; pickupId: string }
  | { type: 'debug-force-win' }
  | { type: 'debug-force-lose' };
```

说明：

- 首版如不想把整套实时物理全塞进 `dispatch`，可以把 `tick` 简化成较粗粒度模拟
- 但 `debug-force-win` / `debug-force-lose` 必须保留，服务流程验证

## 7.4 Metrics

推荐：

```ts
export interface PinballPetMetrics {
  score: number;
  combo: number;
  highestHitCount: number;
  defeatedEnemies: number;
  spawnedExtraBalls: number;
  status: RoundOutcome;
}
```

这些指标未来可直接喂给：

- 任务系统
- 结算面板
- 排行榜

## 8. 任务事件映射建议

当前项目已有任务事件适配思想，新的弹球玩法也应尽早产出事件。

推荐首版事件：

1. `launch_count`
   发射次数

2. `enemy_defeat`
   击败敌人数

3. `combo_reach`
   达成指定连击数

4. `extra_ball_gain`
   获取额外球数

5. `skill_use`
   使用精灵技能

6. `stage_clear`
   通关关卡

7. `boss_clear`
   通关 Boss

8. `score_reach`
   单局分数达到阈值

首版不需要一次性把所有任务都做完，但事件接口要留。

## 11. 数值与配置建议

## 11.1 首版关卡配置

每关建议可配置：

```ts
interface StageConfig {
  id: string;
  name: string;
  waves: WaveConfig[];
  startBalls: number;

  loseLine: number;
  reward: {
    coins: number;
    petXp: number;
    shards?: Array<{ petId: string; amount: number }>;
  };

```

## 11.2 首版目标值建议

- 开局球数：`10~20`
- 单回合额外球收益：`0~5`
- 普通局总回合：`5~12`
- Boss 局总回合：`8~15`

数值原则：

- 首版宁可偏爽，不要偏抠
- 先验证循环，再收紧平衡

## 12. 快速胜负与调试支持

因为当前项目强调流程验证，所以必须保留开发期流程按钮。

后续实现时必须支持：

1. `debug-force-win`
   不需要真的清完关卡，直接进入胜利结算

2. `debug-force-lose`
   不需要真的顶线失败，直接进入失败结算

3. `loadSnapshot / persistSnapshot`
   至少支持回合起点恢复

这三项优先级高于复杂玩法细节。

---

## 13. 营地与养成在首版如何挂接

局外不需要先做完整营地系统，但要给后续留位置。

首版建议只做最简映射：

- 精灵等级 -> 提升基础伤害 / 技能系数
- 精灵星级 -> 提升额外效果触发率
- 精灵进化 -> 解锁新的被动或技能形态

营地系统首版可以只作为文本 / 数据占位：

- 孵化屋等级
- 训练场等级
- 研究所等级

先让这些字段能影响战斗初始值即可。

## 14. 实现顺序建议

按下面顺序做，不要乱序：

1. 建立 `pinballPet` module 基础类型
2. 做最小可运行战斗循环
3. 做胜负判定与 settlement 回流
4. 接 snapshot 存档
5. 接 3 只精灵与 4 条基础技能
6. 接任务事件
7. 接关卡配置
8. 最后再做细节表现与营地映射

1. `先接流程，再扩玩法`
2. `先做 MVP，再扩养成`
3. `先保证模块替换成功，再谈全局重构`

这三条必须长期有效。
