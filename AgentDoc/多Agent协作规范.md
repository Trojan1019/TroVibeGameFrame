# 多 Agent 协作规范

这份文档用于约束当前项目在多会话、多代理并行开发时的工作方式。

目标不是提高抽象完整性，而是降低下面三类风险：

- 同一文件同一区域被多个 agent 同时改写
- 共享原语和公共入口被顺手重构，导致其他会话大面积冲突
- 一个任务的局部需求演变成跨模块扩散修改，破坏合并稳定性

---

## 1. 核心原则

并行开发时，默认遵守三条核心原则：

1. 缩小改动面
2. 先读后改
3. 把冲突面显式隔离

这三条不是建议，而是默认执行约束。

---

## 2. 缩小改动面

每个 agent 只应修改当前任务直接相关的内容：

- 当前页面
- 当前模块
- 当前资源映射层
- 当前文档

禁止：

- 顺手修 unrelated UI
- 顺手统一命名
- 顺手做全文件格式化
- 顺手把局部需求上升为全局架构重写

如果任务是 icon、交互、布局、文案、流程中的某一个，就优先把变更锁在这一层，不扩散到其它层。

---

## 3. 先读后改

不要依赖之前会话中读过的内容直接下补丁。

每次真正修改前，必须重新读取目标文件，确认：

1. 文件还在原路径
2. 目标区域没有被其他 agent 刚改过
3. 当前方案仍然适配最新上下文

如果发现目标区域已经被改过：

- 先判断能否改到更外层的适配层
- 再判断能否拆到新文件
- 不能安全落地时，停止继续覆盖，先与用户同步

---

## 4. 把冲突面显式隔离

能新增，不覆盖。

优先顺序：

1. 新增独立资源文件
2. 新增映射层 / registry / adapter
3. 新增 wrapper 组件
4. 通过可选参数扩展共享组件
5. 最后才直接改共享原语本体

例如：

- 要换 icon，优先新增统一 icon registry，而不是立即全局替换所有页面
- 要改对局交互，优先在 `GameScreen` 外层补交互状态，而不是改玩法规则模块
- 要换视觉风格，优先改 `shell` wrapper，不直接散改业务页面

---

## 5. 高风险共享区

下面这些区域默认视为高风险共享区，多个 agent 不应同时重写：

### 5.1 流程与状态入口

- `Game/src/App.tsx`
- `Game/src/framework/*`
- `Game/src/games/registry.ts`

风险：

- 容易影响大厅、对局、结算整体流程
- 任何小改动都可能与其它会话冲突

### 5.2 共享壳层原语

- `Game/src/components/shell/ShellPrimitives.tsx`
- `Game/src/index.css`

风险：

- 影响全局按钮、面板、钱包、图标、动效
- 一次改动会波及多个页面

### 5.3 资源映射与公共 icon 层

- `Game/src/components/shell/AnimalAssetIcon.tsx`
- `Game/src/components/shell/GameResourceIcon.tsx`

风险：

- 容易造成语义漂移
- 影响大厅、对局、商店、奖励弹窗等多个界面

高风险共享区的工作规则：

- 修改前必须重读文件
- 只做局部补丁
- 尽量保持向后兼容
- 不做顺手整理

---

## 6. 低冲突优先策略

如果项目明确存在多个 agent 并行，优先按下面方式拆任务：

- 一个 agent 只做 icon 资产与映射层
- 一个 agent 只做交互/反馈
- 一个 agent 只做文案/流程
- 一个 agent 只做布局/适配

尽量避免：

- 两个 agent 同时改同一个共享文件
- 一个 agent 改资源语义，另一个 agent 同时改资源调用方

---

## 7. 文件级工作建议

### 7.1 适合并行的区域

- 单个 modal 页面
- 单个玩法模块 view
- 独立文档
- 独立资源文件

### 7.2 不适合并行的区域

- 全局状态入口
- 全局 shell primitives
- 全局样式入口
- 公共 registry / adapter

---

## 8. 修改策略

当发现潜在冲突时，优先按下面顺序处理：

1. 改为新增文件
2. 改为新增 wrapper
3. 改为新增参数，保持旧接口可用
4. 改为只更新文档，不立即落代码
5. 如果仍冲突，暂停并与用户确认

不要直接覆盖其他 agent 可能正在使用的共享实现。

---

## 9. 验证要求

即使是局部任务，也要验证“没有把别的会话正在依赖的东西搞坏”。

默认最小验证：

- `npm run lint`
- `npm run build`

如果改动涉及浏览器可见层，还应至少补一次本地页面检查。

---

## 10. 对后续 Agent 的执行要求

如果你是后续进入本项目的 agent，并且发现项目正在并行开发：

1. 先读 `AgentDoc/README.md`
2. 再读本文件
3. 明确自己当前任务属于哪一层
4. 明确本次不修改哪些共享区域
5. 修改前重新读取目标文件

如果做不到这五步，不应直接开始改共享代码。
