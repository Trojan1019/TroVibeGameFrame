# 双精灵物理弹球 UI 与战斗策划案

更新时间：

- 2026-07-06

文档目的：

- 基于用户提供的参考图，重新定义本项目的主战斗玩法
- 把当前“伪动态回合结算型”方案，转成“上方发射口 + 下方随机方块 + 真实物理碰撞”的结构
- 给后续实现提供统一的 UI、战斗规则、物理要点和数值边界

适用范围：

- `playing` 主战斗页
- 双精灵出战系统
- 局内物理战斗 runtime
- 关卡生成与回合推进规则

---

## 1. 结论先行

新的主玩法应定义为：

- `双精灵实时物理弹球战斗`

一句话描述：

- 玩家每局只携带两只精灵，从上方中央发射口释放一串小球；小球遵循真实反弹规则，在下半场随机分布的敌方数值块之间碰撞清除；球落到底部后被回收，并在下一轮重新回到上方发射区；场内还存在左右弹力球和顶部三洞传送结构，用来制造高收益反弹线路。

这套玩法与上一版草案的关键差异：

1. 发射方向改为 `上 -> 下`
2. 敌方生成区域改为 `下半场`
3. 敌方移动方向改为 `逐回合上移`
4. 敌方位置不再走五列格子，而是 `连续 x 轴随机分布`
5. 核心乐趣从“算离散角度”改成“看真实碰撞与弹道利用”
6. 每局只允许 `2 只精灵出战`

## 2. 参考图拆解

从参考图可确认的布局特征：

1. 顶部中央有主发射口
2. 顶部左右两侧各有一个 `+1` 奖励环
3. 顶部边缘存在三个洞口
4. 左右两边墙体向下延伸，形成封闭弹道空间
5. 场内主体为空旷物理空间，不是固定棋盘格
6. 方块和圆环目标散落在下半区域，位置有角度和错位感
7. 底部是回收带，小球触底后不会继续留场，而是回收到下一轮

从用户补充规则可确认：

1. 上方左右两边有“弹力球”
   作用：大幅弹飞小球，制造高价值折返轨迹
2. 左右洞口进入后，会从中间洞口继续出现
3. 一次游戏只能出战两只精灵
4. 发射口旁边必须有“切换精灵”按钮
5. 方块位置是 `连续随机 x 坐标`
6. 方块不是沿五分点排布
7. 每回合推进时，敌方整体 `上移`

## 3. 与当前项目风格对齐的视觉约束

这份方案的视觉实现必须继续服从当前项目已经建立的壳层语言，不另起一套“深色街机 / 科幻霓虹”风格。

当前项目已确认的主风格：

- 浅色天空到地面过渡背景
- 奶白 / 淡蓝纸片感面板
- 大圆角卡片与圆角胶囊按钮
- 蓝灰主色文字与按钮
- 轻拟物阴影，而不是厚重金属高光
- 可爱、轻松、休闲小游戏感

因此新战斗页必须满足：

1. 外层继续像现有 `Lobby` / `Settlement` / `Shell` 页面，而不是突然切成重科幻战斗场景
2. 主战场可以比大厅更聚焦，但只能做成“浅暖色竞技盘 + 轻层次内框”，不能做成黑底霓虹街机厅
3. 状态条、数值卡、双精灵卡、技能按钮必须继续复用现有的圆角卡片、浅色渐变、蓝灰文字语言
4. 强反馈只放在球体、命中特效、技能附魔色，不应该让整页背景和外框过度发光

建议直接沿用的现有风格锚点：

- `ShellScreen` 的天空系背景
- `ShellPanel` 的白纸卡片质感
- `ShellButton` 的蓝色主按钮与浅色中性按钮
- `ShellTitle` / `ShellWalletChip` 的圆角胶囊信息样式

## 4. 新战斗页布局定义

## 4.1 页面分区

战斗页从上到下拆成 5 个区：

1. `顶部状态栏`
   显示暂停、得分、回合数、当前球量、局内货币

2. `顶部机关带`
   包含主发射口、左右弹力球、三洞口结构、双精灵切换按钮

3. `主物理战场`
   小球、敌方方块、圆环目标、掉落物、命中特效都发生在这里

4. `底部回收带`
   所有小球触底后统一回收，不在底部二次反弹

5. `底部功能条`
   显示当前两只精灵、主动技、道具按钮、回合说明

## 4.2 UI 结构建议

### 顶部状态栏

左侧：

- 暂停按钮
- 音效按钮

中部：

- 总分
- 当前回合
- 连击峰值

右侧：

- 菜单按钮
- 剩余球数
- 当前激活精灵头像

### 顶部机关带

中间：

- `主发射口`
- 发射口下方显示当前待发球数

发射口左侧：

- `精灵切换按钮`
  作用：在两只出战精灵之间切换“本轮发射附魔”

发射口右侧：

- `精灵主动技按钮`
  作用：释放当前激活精灵的主动技能

顶边左右：

- `侧弹力球`
  大球造型，发光，命中后大幅增速并改变反射角

顶部三洞：

- `左洞`
- `中洞`
- `右洞`

规则：

- 左洞、右洞是入口
- 中洞是出口
- 球进入左右洞后，会有极短隐藏飞行时间，然后从中洞射出

### 主物理战场

视觉特点：

- 外层保持浅色壳层背景，不脱离当前项目页面基底
- 战场本体用浅暖奶油色到淡琥珀色渐变盘面
- 内框可比大厅更深一层，但仍应是焦糖 / 深棕灰的温和边框
- 允许少量点状粒子与云雾层次，但不做满屏星空
- 方块有不同旋转角，体现“漂浮危险物”的感觉

### 底部回收带

建议做成：

- 一条浅棕灰回收槽，与主战场边框属于同一材质体系
- 中央有柔和能量吸入口特效
- 小球触底后缩小、发光、飞回顶部缓存区

### 底部功能条

左侧：

- 精灵 A 头像卡
- 精灵 B 头像卡

中间：

- 当前激活精灵说明
- 被动标签

右侧：

- 道具按钮
- 回收加速按钮

## 5. 双精灵出战规则

## 5.1 出战限制

每局只能上阵两只精灵：

- `主战精灵`
- `副战精灵`

不再使用三宠同场常驻逻辑。

## 5.2 精灵职责

主战精灵：

- 决定当前发射球的元素属性
- 决定本轮普通命中的附加效果
- 决定主动技能释放结果

副战精灵：

- 提供常驻被动
- 提供回合触发型辅助效果
- 不直接改变发射口外观主色

## 5.3 切换逻辑

玩家每回合可在发射前点击切换按钮：

- 切换当前激活精灵
- 改变本轮球体附魔
- 改变本轮主动技按钮内容

限制：

- 发射后直到本轮所有球回收结束前，不能切换

## 5.4 精灵示例分工

火系主战：

- 命中叠灼烧
- 主动技：下一串球附带爆炸溅射

雷系主战：

- 命中后链式跳电
- 主动技：命中低血量块时追加穿透

冰系副战：

- 回合结束时冻结最靠上的 1 个目标，令其下一轮不上移

风系副战：

- 球回收时额外返还 1~2 颗球

## 6. 物理战斗规则

## 6.1 基础循环

单回合流程：

1. 玩家选择当前激活精灵
2. 玩家拖拽瞄准
3. 从上方主发射口连续喷出一串小球
4. 小球在场内进行实时碰撞
5. 所有球触底后进入回收
6. 回收结束
7. 敌方全体上移一段距离
8. 生成新目标 / 新机关
9. 进入下一回合

## 6.2 球体行为

小球应遵循真实物理碰撞表达：

- 与左右边墙反弹
- 与顶部斜边反弹
- 与方块按碰撞法线反弹
- 与圆形目标按圆心法线反弹
- 与侧弹力球碰撞时获得高反弹系数
- 进入洞口后临时隐藏，并从中洞重新发射

底部规则：

- 球触底不再反弹
- 立即标记为 `returned`
- 播放回收动画
- 不再参与本轮碰撞

## 6.3 发射规则

建议采用连续发射而非一次性团发：

- 每颗球间隔 `40~65ms`
- 发射串长度 = 当前持有球数

这样可以保留：

- 连续弹幕感
- 多球错峰反弹
- 更好的爽感积累

## 6.4 顶部洞口传送规则

传送规则定义：

- 左洞入口：球进入后，`150~220ms` 后从中洞射出
- 右洞入口：球进入后，`150~220ms` 后从中洞射出
- 中洞默认只出不进

中洞出射角：

- 优先继承入洞前速度方向
- 但会压成一个朝下扇区角度，避免无意义贴顶横飞

目标：

- 让玩家把左右洞口当作“弹道重定向机关”

## 6.5 左右弹力球规则

左右弹力球不是普通墙体。

命中后效果：

- 恢复速度到高阈值
- 反射角更大
- 可附加一次短时发光拖尾

设计目标：

- 提供“高价值回弹点”
- 鼓励玩家打边路高收益线路

## 6.6 敌方块规则

敌方目标分两类：

1. `方块`
   主要清除对象

2. `圆环目标`
   轻量特殊目标，可承载 buff / debuff / 召唤

方块属性：

- `hp`
- `size`
- `rotation`
- `massLevel`
- `tags`

建议表现：

- 小角度旋转
- 不是 rigidbody 自由翻滚
- 命中时允许轻微抖动
- 不建议让方块被真的撞飞

原因：

- 真正刚体堆叠会导致读局混乱
- 本玩法核心是“球动态、目标稳态、位置随机”

更稳的方案是：

- 位置固定
- 仅做命中抖动和视觉旋转

## 6.7 敌方位置生成

本玩法必须使用 `连续坐标生成`，不走离散列。

生成规则：

- 每个目标有独立 `x` 坐标
- `x` 取值范围受边墙和已有目标间距限制
- 每个目标的 `y` 按生成带分层落位
- 保证最小间距，避免重叠

建议约束：

- 方块与方块中心距 >= `1.15 * blockSize`
- 方块与圆环中心距 >= `1.1 * blockSize`
- 方块不能刷在左右弹力球正下方的安全禁区
- 方块不能刷进洞口出射路径起点禁区

## 6.8 回合推进方向

敌方推进方向定义为：

- `每回合整体上移`

失败条件：

- 任意敌方目标上沿触碰到顶部警戒线
- 或侵入发射口保护区

这样与参考图一致：

- 发射口在上
- 威胁从下往上逼近

## 7. 局内目标与胜负

## 7.1 单局目标

每局的主目标：

- 在敌方推进到顶部前清空当前关卡目标

局内辅助目标：

- 打出高连击
- 触发洞口传送
- 利用弹力球完成高倍率折返
- 用双精灵组合打出连锁收益

## 7.2 胜利条件

任意一种成立即胜利：

- 清空 Boss 核心目标
- 清空当前关卡全部主要敌方块
- 在限回合挑战中达成指定击破数

## 7.3 失败条件

任意一种成立即失败：

- 敌方块到达顶部失败线
- Boss 特殊推进占据发射区

## 8. UI 设计稿说明

## 8.1 设计关键词

- `浅色休闲战斗页`
- `纸片感壳层`
- `上方机关感`
- `下方危险堆积`
- `双精灵附魔切换`

## 8.2 画面重心

这张图的重心必须放在：

- 顶部机关带
- 中部长弹道
- 下部危险块堆积

不是传统居中棋盘，不是卡牌战斗框。

## 8.3 关键视觉锚点

1. 顶部中央发射口必须是第一视觉锚点
2. 左右弹力球必须一眼能看出“撞上去会弹很远”
3. 三洞结构必须清晰可理解
4. 两只精灵必须明确展示“当前激活的是谁”
5. 底部回收带必须让玩家理解“球掉下去会回来”

## 8.4 精灵 UI 呈现

推荐底部双卡：

- 左卡：精灵 A
- 右卡：精灵 B

激活态表现：

- 卡边高亮
- 发射口光色同步
- 球体拖尾同步元素色

切换反馈：

- 点击后发射口光圈切色
- 当前技能按钮内容变化
- 顶部小提示：`已切换为雷羽雀附魔`

## 8.5 与现有项目一致的具体落图要求

设计图必须显式保留下面这些项目味道：

- 页面底色仍然是浅蓝灰天空渐变
- 顶部状态信息优先用白底胶囊 chip，而不是悬浮科幻 HUD
- 快速完成按钮继续放在一个浅色浮层卡片里，不改成金属操控台
- 双精灵卡要像当前页面已有宠物卡一样，白底、淡色描边、轻阴影
- 主技能按钮继续是大圆角主按钮逻辑，可在颜色上略偏暖金，但不能脱离当前按钮体系
- 所有文案区继续使用深蓝灰字色，不切成高饱和荧光字

如果后续要出图，应该理解成：

- `当前项目风格里的战斗页`

而不是：

- `为这个玩法重新发明一套新美术风格`

首版必须做：

1. 上方中央发射口
2. 连续发射小球
3. 小球真实反弹
4. 左右弹力球
5. 左右洞口进、中洞出

7. 下半场随机 x 坐标敌方块
8. 敌方逐回合上移

10. 发射前切换精灵

首版可以先不做：

1. 方块真实刚体翻滚
2. 复杂地形移动机关
3. 太多精灵技能分支
4. 多层地形碰撞材质
5. 多段 Boss 机关

## 10. 技术实现约束

## 10.1 推荐实现方式

应采用：

- React 负责 HUD、按钮、精灵卡、结算
- `canvas` 负责主战场渲染
- 独立 `runtime` 跑 60FPS 固定步长物理循环

不建议继续沿用：

- 纯 React 状态驱动每一步弹道
- 五列格子逻辑
- 发射即一次性结算

## 10.2 存档边界

存档只记录：

- 当前关卡
- 当前回合
- 当前球数
- 双精灵配置
- 当前敌方块位置与血量

不存：

- 半空中的球
- 当前帧速度
- 实时粒子特效

存档恢复时：

- 直接回到“新回合待发射”状态

## 11. 给实现代理的摘要提示

后续实现时，必须遵守下面几条：

1. 不再使用五列棋盘
2. 不再使用“下方发射、上方掉落”的旧逻辑
3. 战场主体必须是实时物理弹球
4. 敌方目标使用连续坐标随机分布
5. 每局只允许两只精灵出战
6. 发射口旁边必须有切换精灵按钮
7. 左右洞进、中洞出必须做成显性机关
8. 左右弹力球必须能明显改变弹道收益
